# Internal local generation worker (LG-2A / LG-2B / LG-2C)

This is an operator-provisioned Windows evaluation slice, disabled in Kavero by default. It is not the public managed installer. Users must not be sent these commands; LG-3 owns complete in-app provisioning. No ComfyUI or Python is used by this worker.

The only accepted profile is the LG-1 pinned Qwen Image 2.1 Q4 package on the recorded RTX 4060/driver/Vulkan inventory. Its license is research/evaluation-only. These scripts do not establish commercial-use or redistribution permission. Only hashes/metadata are committed, not weights or native binaries.

## Runtime

- Verified host Node: **24.11.1**, including its experimental built-in SQLite. Other versions fail closed pending verification.
- `provision.mjs <absolute-package-root> <absolute-private-state-root>` creates an isolated private config with a random server-only secret; Windows ACLs restrict the directory to the current account. Do not put private state in a public directory or commit it.
- `worker.mjs serve <absolute-private-config.json>` owns a loopback-only bridge on port 8791. The pinned package is verified at startup and again by each supervisor before native launch. Admission checks the verified file snapshot and hardware identity; changed files invalidate readiness.
- Internal app configuration requires `KAVERO_LOCAL_GENERATION_INTERNAL=1`, a fixed `KAVERO_LOCAL_BRIDGE_URL` (loopback or Docker host bridge) and `KAVERO_LOCAL_BRIDGE_SECRET` matching the private config. These are server-only. Leave the flag unset outside internal evaluation. Do not log or display the secret.
- Internal UI additionally requires `KAVERO_LOCAL_GENERATION_UI_INTERNAL=1`. Both flags are server-only and unset by default; no public catalog entry is added. `/generate` renders the Cloud/Local preview selector only with both flags. The authenticated readiness route returns only needed free-memory and storage summaries, not paths, package/device IDs or bridge secrets. This is an internal evaluation UI, not the LG-3 public installer.
- The compact local panel sends the shared exact 512x512/count-one/text-only intent directly to the durable job API. References, an open cloud result/edit session, active cloud generation or Sequence block switching. Cloud settings are retained; local controls do not forward cloud reasoning/quality/background/count options. Overlong prompts remain intact and are rejected visibly at 1,000 UTF-16 code units, matching server validation.
- Each tab stores the pending submission key/intent before admission in authenticated-owner-scoped session storage. Refresh restores the existing job, or offers Check submission with the same key when admission acknowledgement was lost. New inference requires explicit Create image/Create another. Storage-disabled browsers cannot safely submit because the pending key cannot be retained. Closing the tab clears this resume hint; server jobs/receipts remain durable, but cross-tab job discovery is not provided in this internal UI.
- Generated images offer Download and explicit Save to Gallery/Retry save. Saved images use Gallery content after staging cleanup. Inference location and save destination are shown separately. Unverified Drive local saving is unavailable in the UI; it never switches the configured destination to another provider. Queue/offline/reconnect/cancel/invalid/expired/deleted states stay distinct; low-memory work waits without changing settings.
- Existing local Supabase bootstrap scripts apply `supabase/migrations/202610020001_local_generation_jobs.sql`, `202610020002_local_generation_outputs.sql` and `202610030001_local_generation_saves.sql`. The Docker bootstrap image includes all three. Do not apply them to a hosted project as part of this phase.

## Safety and lifecycle

The app records owner/key/normalized-intent identity before contacting the worker. The host ledger atomically admits the same owner/key/job once, reserves one device claim globally, and admits at most five outstanding jobs/two per owner. Queued work survives coordinator restart. Each detached supervisor records an epoch, unique claim token, OS process creation identity and heartbeat; it owns one native process directly. Lost acknowledgements are reconciled by the same job. Durable ledger identity prevents resubmission into a replacement/empty ledger.

Stale dispatch/running/cancellation claims become `submission-unknown` and retain device capacity. A surviving supervisor can publish a late terminal receipt. If it cannot, recovery stays unknown; never reclaim on a timeout or kill an arbitrary PID. An internal operator can run `recover.mjs <private-config.json> <job-id>` for a stale unknown claim. It checks OS process creation identity and private claim/job attribution twice, refuses live or incompletely inspected processes, and restores only a private unvalidated output or a failed job. It does not kill processes or retry inference. No automatic native retry, resolution/quantization reduction or global GPU interrupt exists.

Queued cancellation is atomic. Active cancellation is a durable request delivered to the owning supervisor and confirmed only after its child exits. GPU memory is checked before dispatch; a verified engine/identity is not a promise of currently free memory. Other applications can still consume the GPU. The generic engine server API is not exposed.

Inference completion remains `generated-unvalidated` to preserve the job contract; output availability is separate: `pending`, `generated`, `invalid`, `expired`. The pinned final PNG must pass regular-file/path/age/single-link checks, CRC/structure checks and complete bounded decoding as one 512x512 RGB/RGBA image. Encoded bytes are capped at 32 MiB; decoded bytes at the exact scanline size. APNG, incompatible dimensions/format, previews and unrelated paths are rejected. An immutable checksum/size/completion/expiry descriptor binds the owner, job, intent, package, device and durable ledger. Every download rechecks the bytes; the app validates them again against its immutable database descriptor.

With the internal flag enabled, `GET /api/local-generation/jobs/<id>/output` offers an authenticated owner-only staged PNG attachment. Downloads inspect existing work only and cannot trigger inference. Unready, invalid and expired outputs return 409, 422 and 410; disconnected runtime/storage returns 503 for reconnection. An expired durable descriptor returns 410 even without the worker. The default flag, public model catalog and generation UI remain unchanged. No paid provider or planning model is called.

## Recoverable saving

`GET /api/local-generation/jobs/<id>/save` reads owner-only save status; `POST` with an empty body or `{}` saves/retries the existing job. Requests cannot choose owners, IDs, refs, filenames, destinations or providers. The server uses configured storage: `kavero-managed` with the registered filesystem/Supabase backend, or connected Google Drive. Inference location remains the local host; a Drive save still sends the finished image/metadata to Drive. This does not promise offline operation or local-only data.

The local save ledger reserves stable Gallery generation/image IDs, output SHA256, frozen destination identity and exact image/metadata object mappings before uploading. A dedicated local persistence path preserves the existing cloud helper's behavior. Managed object paths include the reserved IDs and use create-only uploads; existing bytes are checked against frozen SHA/size. Drive reserves file IDs before creating either file, verifies parent/MIME/size/job/checksum and exact bytes, and reconciles retries of those same IDs. No folder replacement, destination fallback, overwrite or uncertain-object deletion occurs. Unidentified/missing Drive accounts/folders fail closed.

Save states are unsaved/saving/save-failed/saved, separate from inference/output state. One attempt owns a **120-second database lease**, renewed every 15 seconds while its **90-second work deadline** remains active. It also holds/renews the accepted **60-second staging lease** when native bytes are needed. An expired attempt cannot publish or update another attempt. Already-started managed backend IO may outlive a request/deadline; immutable create-only keys plus fenced publication make its late result safe to reconcile. Busy competing requests receive 202 with the same IDs.

Partial uploads and uncertain upload/database acknowledgements retain durable mappings. A retry reads and verifies existing objects first, uploads only missing ones and atomically publishes both Gallery rows with the saved receipt. If the final image already exists, metadata/database recovery can finish after native staging expires or disconnects. Confirmed partial final objects are retained for that recovery; they are not automatically deleted as failed uploads. Source expiry without a confirmed final image returns 410; conflicts/destination changes return 409; disconnected/full storage or uncertain database returns 503. Download remains available until the original source expiry.

After successful publication, signed `/saved` acknowledges the frozen output SHA to the host. It makes staging eligible for cleanup once active leases release. Losing that acknowledgement is safe: saved replay/status retries it and ordinary 24-hour expiry remains the fallback. Saved images are downloaded through existing Gallery content routes after staged files are cleaned. A saved receipt is a tombstone: replay after explicit Gallery deletion reports `historyRemoved` and never resurrects rows/files or inference. Returning final storage/Gallery data does not depend on a current provider selection.

## Staging and retention

- Durable reservations: **64 MiB per admitted job, 1 GiB total**, including retained results and unknown work. Admission also checks free bytes on the actual state volume with 256 MiB of headroom. Reservations are made under the global SQLite write lock; same-job replays bypass new reservations. A full stage returns 507. Reservations are released only after exact mapped files are cleaned; job/key tombstones remain.
- Engine stdout/stderr is bounded to **4 MiB**. Log overflow/write failure terminates only the owned native child; its exit/pipe closure precedes a terminal receipt. A 250ms file monitor stops an oversized or linked output. These are safeguards for the pinned 512px engine contract, not an OS filesystem quota for arbitrary executables.
- Generated unsaved outputs expire **24 hours after the terminal completion receipt**, recorded as explicit timestamps. Staged logs/prompts/finals are cleaned on the coordinator's periodic tick once expired or confirmed failed/cancelled. Old LG-2A completed records are validated through the same gate after restart. Unknown/running work never releases its staging reservation or deletes files.
- Private signed `/lease`, `/lease/renew` and `/lease/release` support the following save slice. Leases last **60 seconds** and can be renewed while active. New leases cannot be acquired after output expiry. Active leases prevent cleanup across coordinators and survive restart; abandoned leases expire. Owner/job/ledger/token are checked. No browser receives the bridge secret or lease management API.
- A normal download holds a lease while reading/validating into bounded memory, then releases it before network delivery. Cleanup can subsequently remove the file without invalidating bytes already buffered for that response. A future save can hold/renew its explicit lease throughout its operation.
- Cleanup checks all directory entries before deletion, refuses symlinks/junctions/unmapped files and deletes only `final.png`, `prompt.txt`, `engine.log` in a mapped UUID job directory. It never recursively deletes a computed path. Interrupted cleanup is retried; missing/disconnected staging roots do not release reservations. No unrelated runtime output is served or removed.

The scoped internal basic checkpoint includes real browser password authentication, two users, concurrent same-key requests, changed-intent rejection, refresh, native generation and cross-store status, queued/active cancellation and controlled native-fault recovery. Explicit abandoned-claim recovery is verified with real OS inspection and a protocol fixture; live-process refusal/PID-reuse cases and resource-pressure guards use focused test fixtures. Actual GPU OOM stress and physical host suspend/resume are untested; the user authorized skipping sleep during basic checks. Retain those limitations for pre-public-release system verification in LG-3. Cold/long protocol evidence must not be mislabelled as real inference. Public clean-host installation remains LG-3.

## Managed installation foundation (LG-3B)

`install/transaction.mjs` provides a host-owned `PackageInstaller`, not a browser API or end-user setup command. Its fixed catalog is supplied by host code. Public mode requires explicit package approval and verified notices; the only current internal catalog entry is a pinned 1062-byte engine MIT notice for transport proof. It contains no inference executable, model or runtime. Qwen evaluation files are not automatically downloadable.

The installer requires verified Node 24.11.1 and native Windows process inspection. A new private instance-marked root contains a SQLite journal, content-addressed cache, resumable parts, per-operation staging and immutable versions. Owner/submission identities survive restart, one process-creation-bound writer protects the destination across connections, and explicit recovery requires two OS observations proving that writer is gone. Timeouts never authorize lock takeover. Cancellation tombstones cannot automatically resume.

Downloads use fixed HTTPS sources, exact redirect host policy, public DNS addresses checked during TLS connection, bounded bodies/deadlines, strong-validator Range recovery and full size/SHA verification. Extraction supports bounded classic ZIP only: 64 MiB encoded, 512 expected files/512 MiB expanded, stored/deflate entries. It refuses traversal, ADS, Windows reserved names, collisions, links and unexpected members. No upstream scripts execute. Actual-volume free-space checks include cache plus staged copies, extraction and 1 GiB headroom. This check is not an OS disk reservation; later exhaustion fails without activation.

Installed means exact files plus an atomic immutable receipt; it does not mean ready for inference. Replays rehash installed bytes and refuse changed or extra files. Existing versions, cache and cancelled/interrupted parts are retained; there is no automatic eviction or deletion of user-owned installations. The private root protects against other Windows accounts; it is not a sandbox against malicious code running as the same account or an administrator.

LG-3C.1 connects this foundation to existing startup and provisions the host runtime/private agent; LG-3C.2 owns worker lifecycle and job-safe activation. LG-3D retains eligible public-package and clean-install/UI release gates. Users will not need a separate ComfyUI/Python installation or manual commands.

## Automatic host bootstrap (LG-3C.1)

The existing `pnpm setup:run` / setup wizard launch now automatically prepares the managed host on Windows x64. Other platforms retain the existing Docker command and do not gain local-inference support. The host root is derived from the project directory under `%LOCALAPPDATA%/Kavero/hosts/`; it is private, instance-marked and independent of evaluation files. No new user command or engine configuration is required.

Kavero pins the official standalone Node 24.11.1 Windows executable (89,894,400 bytes) and full upstream Node/dependency license (143,310 bytes). Both sources, sizes and hashes are fixed in `host/runtime.mjs`. Bootstrap reuses the secure downloader, creates a verified temporary Node seed and uses that exact runtime to publish/replay the LG-3B installation receipt. Seed/cache/installed copies and headroom are included in disk checks. The seed is removed only after verified publication. Project bootstrap Node does not import SQLite or need to match the host runtime version.

A Windows kernel mutex excludes concurrent launchers. Its hidden helper releases ownership when the launcher pipe closes; timeouts never authorize takeover. Stable private configuration stores the instance, secret and runtime submission key. A copied content-addressed agent runs on signed loopback port 8792, with bounded requests, durable replay-nonce protection and signed status/shutdown replies. Process creation identity, epoch, code and runtime fingerprints must match before reuse or shutdown. Responsive unknown ports/identity drift fail closed; no arbitrary process is killed. An exited launcher can reattach its still-owned idle agent on the next run.

The launcher automatically adds a private Compose overlay carrying server-only host URL/secret. Neither `.env.docker.local` nor browser variables receive new secrets. Ordinary shutdown confirms the owned agent has exited before releasing the mutex. External Compose without the Kavero launcher does not create this managed connection.

With normal startup the agent reports `awaiting-package` or `evaluation-disabled`, and `inferenceReady:false`. LG-3C.2b adds internal managed activation below. Public model/UI release still waits for LG-3D.

## Worker lifecycle guard (LG-3C.2a)

The generation ledger now holds a durable token-bound maintenance barrier. It rejects new submissions while preserving same-job retry receipts and allowing already-queued work to drain normally. Queued, dispatching, running, cancellation-requested and submission-unknown jobs all prevent a quiescent stop. A timeout never releases the barrier or turns uncertain work into permission to update.

Signed internal `/lifecycle/pause`, `/lifecycle/status`, `/lifecycle/resume` and `/lifecycle/stop` require the current worker epoch, ledger identity, maintenance token and purpose. Readiness is unavailable during maintenance; owner status, downloads, save leases and cancellation remain available. The stop response says `stopping`, not that process exit has been confirmed. Close waits for the coordinator tick and HTTP server to finish, shares its completion across callers, and refuses outstanding work. Supervisors/native processes are not killed by lifecycle stop. Resume requires an explicit matching token against the current worker epoch; the barrier survives restart.

LG-3C.2b wires this guard into managed activation below. Public users still have no manual worker setup requirement or new wizard step.

## Managed worker activation (LG-3C.2b)

The private content-addressed bundle now includes the complete worker import graph, pinned profile and PNG decoder. Node 24.11.1 executes the bundled TypeScript decoder without application dependencies. Agent/worker runtime does not import source or dependencies from the checkout. Bundle receipts bind every file; changed or additional files invalidate reuse.

The fixed Qwen 2.1 evaluation package has a separate immutable installed receipt binding all image/encoder/VAE/engine files and the original package metadata. The internal proof copies existing verified research bytes into a new private version, checks destination disk, ordinary-file containment and full hashes, and atomically publishes its receipt. This is operator proof tooling, not an end-user import or approved public downloader. No public model is approved. Internal activation requires an explicit trusted bootstrap policy; normal Kavero startup cannot enable this evaluation package.

Signed `/host/activate`, `/host/activation` and `/host/activation/cancel` retain owner/key-bound operations outside HTTP request lifetimes. The double-gated authenticated `/api/local-generation/setup` derives the owner from the existing session and exposes only bounded, sanitized operation/status fields. Browser-supplied owners, package URLs, workflows, filesystem paths and shutdown commands are rejected. Concurrent activation is serialized; cancelled operations remain tombstones; failed/interrupted operations need an explicit same-key retry.

Activation verifies the installed recipe before pausing admission, requires quiescence, and starts the worker inside the owned host agent on port 8791. Queued/running/unknown work prevents replacement while existing work drains. Failed candidate startup restores the previous verified fixed package and keeps its ledger; if recovery fails, readiness stays unavailable. The active pointer and installed acknowledgement commit together. An owned shutdown barrier is reconciled on the next explicit Kavero startup; update barriers require their owner's explicit recovery. Nothing expires into permission to kill work or adopt an unknown process.

The private Compose overlay supplies both host and generation bridge credentials automatically. Secrets and ledger identity survive restart. Real managed/native and Compose proof plus authenticated two-user app checks are recorded in the C.2b report. This evaluation recipe still binds one tested RTX 4060 Laptop GPU/driver/Vulkan mapping; other devices are unsupported. Public eligible-model download, portable hardware assessment and compact install UI remain LG-3D. Physical sleep, actual GPU OOM and live Drive local saving are not accepted by this checkpoint.

## Preflight diagnosis and research delivery inventory (LG-3D.1)

The private SQLite job ledger has an optional `failure_receipt`: a fixed stage, fixed reason code and UTC timestamp. The supervisor records it for caught preflight failures or uncertain inference errors, fenced by the current claim. Resource checks keep the original 6 GiB available VRAM, 8 GiB available RAM and 1 GiB free staging thresholds; invalid measurements now fail closed. No prompt, stderr, path, command or arbitrary exception text goes into the receipt. It survives restart; old failed jobs have no invented cause. Confirmed cancellation/success clears uncertainty, terminal receipts cannot be rewritten, and no reason authorizes automatic retry or smaller settings.

Owner-only worker status and authenticated app reconciliation return this bounded diagnosis with a fixed explanation. The application does not add a Supabase diagnostic column: the private worker ledger is authoritative, and disconnected app status may remain generic. A stale polling result cannot attach a diagnosis to a newer checkpoint state. Diagnostics do not classify arbitrary native exit codes or retroactively explain C.2b's first failure. The compact installation UI consumes these fields in D.2.

`install/qwen-research-audit.json` binds all 25 existing payload files, the four fixed upstream artifact sources, pinned cards/licenses/source notice provenance and a full terms-file digest. `notices/qwen-research-v1/` holds 29 bounded notice/evidence files (148,373 bytes); model weights are not present there. Image/VAE terms are research/evaluation only; the pinned official encoder card declares Apache-2.0. The engine archive already contains the engine/ggml MIT notices under `.txt` names. Historical reports are preserved; the new audit corrects the filename-only conclusion.

This is an inventory, not the public installer manifest or approval. `publicApproved` and `noticesVerified` remain false. D.2 must reconcile the unchanged ZIP's bundled binary/frontend dependency inventory, the vendored ZIP library's undeclared revision, modification notices and installed license assembly, then review the actual delivery purpose before network admission/exposure. A free feature, user checkbox or direct-upstream transfer alone cannot establish rights. No blanket additional permission is required for research/evaluation rights expressly granted; commercial purposes require separate rights. The existing package fingerprint, device, generation arguments and immutable model receipt remain unchanged; final delivery notices belong in a separate audited delivery receipt.

## Complete delivery representation (LG-3D.2 package checkpoint)

`install/qwen-delivery.mjs` constructs a host-owned private research delivery manifest from pinned code, the unchanged 25-file native profile, exact recipe metadata and the audited notice digest. It returns four immutable upstream artifacts and 30 bounded bundled texts (29 notice/evidence files plus the recipe). It has no browser input, automatic admission or activation side effect. It rejects changed audit/terms/component sources or notice bytes. Both public approval flags remain false: this is an installer input for research proof, not final delivery approval.

The installer can retain an archive at a separately validated `retainAs` path as well as extracting its exact members. Cache, retained archive, extracted files and notice/metadata staging copies are counted before download; the complete fresh Qwen work estimate is 19,935,070,277 bytes plus 1 GiB free headroom on the actual destination volume. Existing retained versions already consume free space; warm cache/staging is reconciled rather than charged twice. This is a measured-volume admission guard, not an OS space reservation.

Optional `bundledFiles` are restricted to notice or recipe-metadata roles: at most 64 texts, 256 KiB each and 1 MiB combined, canonical base64, strict UTF-8, no NUL, exact size/SHA and ordinary safe paths. They participate in path collision checks, manifest identity, receipt file lists, disk/progress accounting, full staging verification and installed replay. Publication flushes notice files before the immutable receipt/version is published. No bundled script executes. A failed notice write leaves an incomplete private stage, not an installed receipt; explicit retry reconciles the same operation/cache.

The complete candidate has 55 installed files, including every original inference file. Actual HTTPS proof downloaded the 30,067,605-byte pinned engine ZIP and installed its 21 members, retained ZIP, 29 bundled notices and recipe metadata into a new private 52-file engine-only proof version. It verified checksums/receipt, another owner's denial and same-operation replay. This was not a complete model download, native activation or clean-host public acceptance. Full fixed-source image/encoder/VAE delivery, owner-bound terms acceptance, installer/worker coordination and compact UI remain the following D.2 checkpoint. Preserve the final dependency/purpose-review gate before public admission. Users will not manage ComfyUI or files themselves.
